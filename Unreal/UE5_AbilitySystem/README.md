# UE5 커스텀 어빌리티 시스템

어빌리티 / 스탯 / 상태효과 시스템이다. 식별은 GameplayTag로 하고 정의는 데이터로 둔다.
네트워크 동기화 모델까지 포함한다. GAS는 쓰지 않았다. 동기화를 직접 통제하고 네트워크 구조를 얇게 유지하려는 의도다.

동기화는 스냅샷과 해시로 desync를 감지하고 교정하는 계층(`PJAbilitySyncComponent`)까지 담았다.
이 계층을 실제로 주고받는 RPC 전송은 샘플 범위 밖이다.

전체 프로젝트가 아니라 핵심 코드만 추린 샘플이다. 바로 빌드되진 않는다.

## 구조

```
[Subsystem]  PJAbilitySubsystem          정의를 한곳에 등록해 두고 태그로 찾는다
[Component]  PJStatComponent             스탯 저장·집계·모디파이어
             PJStatusEffectComponent     상태효과 관리, 스탯에 반영
             PJAbilityComponent          어빌리티 부여·발동·틱
             PJAbilitySyncComponent      동기화 계층(시스템 밖)
[Runtime]    PJAbility / PJStatusEffect   어빌리티·효과의 런타임 인스턴스
[Data]       PJAbilityData / PJStatusEffectData / PJAbilitySet / PJStatData / PJStatModifier
[Interface]  IPJAbilitySystemInterface   오너 추상화(특정 Pawn 의존 제거)
             IPJTimeSource               시간 소스 추상화(로컬/서버/테스트 교체)
```

스탯·효과·어빌리티 시스템(Component·Runtime·Data)은 네트워크를 모른다. 로컬에서만 돌고, 동기화는 그 위에 얹은
`PJAbilitySyncComponent`가 맡는다. 그래서 동기화 방식을 통째로 바꿔도 이쪽은 안 건드린다.

## 설계에서 신경 쓴 부분

### 스탯

스탯은 두 종류로 나눴다. 공격력·방어력 같은 값은 계산 결과가 곧 스탯이고, HP·마나 같은 자원은
Current(0..Max)를 따로 들고 다닌다.

버프/디버프는 모디파이어로 쌓는다. 각 모디파이어에 소스 핸들을 달아 두면, 효과가 끝날 때 그 소스가 건 걸
한 번에 걷어내 깔끔하게 원복된다. 값은 `(Base + ΣAdd) × Π(1+Mul)` 뒤 Override, Clamp 순으로 계산하는데,
모디파이어를 먼저 정렬해서 적용 순서를 고정한다. 그래서 어떤 순서로 들어왔든 결과가 늘 같다.
그리고 매 프레임 다시 계산하지 않고, 모디파이어가 바뀌면 표시만 해뒀다가 값을 물어볼 때 한 번만 계산한다.

### 상태효과

버프의 남은 시간을 `elapsed += DeltaTime`으로 세면 클라마다 어긋난다. 이벤트를 늦게 받거나 늦게 접속하면 시작점이
달라지니까. 그래서 각 효과는 시작 시각과 지속시간을 들고 있고, 남은 시간은 `Duration − (지금 − 시작)`으로
그때그때 계산한다. '지금'은 서버와 맞춰진 시계(`IPJTimeSource`)에서 가져온다. 이러면 프레임레이트나
접속 시점이 달라도 모두 같은 만료 시점에 도달한다. 독과 회복 같은 주기 효과도 DeltaTime을 누적하지 않고 시간 경계마다 적용된다.

효과는 즉시(힐·데미지) / 유한 / 무한 / 주기로 나뉘고, 스택과 리프레시 규칙을 데이터로 지정한다.

### 어빌리티

어빌리티 발동을 특별하게 다루지 않는다. 코스트는 자원을 깎는 즉시 효과, 쿨다운은 태그를 붙이는 시한 효과로
처리해서, 어빌리티·버프·코스트·쿨다운이 전부 "효과 하나 적용"으로 흐른다. 발동 조건도 태그로 본다.
필요한 태그가 있는지, 막는 태그(예: 기절)가 걸려 있는지 확인한다.

### 동기화

발동 이벤트를 각 클라가 똑같이 재생하고, 결과는 로컬 시뮬레이션에 맡긴다. 접속하거나 화면에 새로 들어온
대상은 그 순간 걸려 있는 효과 전부를 스냅샷으로 한 번 받아 맞춘다(여러 번 적용해도 결과가 같아 안전).

그런데 이벤트만 믿으면, 하나 놓쳤을 때 다시 맞출 방법이 없다. 그렇다고 상태 전체를 계속 복제하긴 무겁다.
그래서 지금 걸려 있는 상태효과를 요약한 **해시 하나만** 두고, 로컬 해시가 서버 것과 다르면 그때만 스냅샷을 다시 받는다.
평소엔 작은 해시 하나만 오가니 부담이 거의 없고, 실제 비용은 어긋났을 때만 든다. 대역폭이 더 빠듯하면 델타 직렬화로 확장할 수 있다.

### 시간

스탯·효과·어빌리티 시스템이 현재 시각을 직접 읽으면, 그걸 서버와 맞추는 일까지 이 시스템이 떠안게 된다. 그래서 시간은 인터페이스(`IPJTimeSource`)로 주입한다.
싱글이면 로컬 시계, 네트워크면 서버와 맞춘 시계, 테스트면 값을 고정한 시계를 넣는다.
무엇을 넣든 이 시스템은 그대로고, 서버 시계를 더 정확히 맞춰야 하면 이 구현만 바꾸면 된다.

## 연결 흐름

1. Owner Actor에 `IPJAbilitySystemInterface`를 구현하고 컴포넌트 3종(Stat/StatusEffect/Ability)을 붙인다.
2. `BeginPlay`에서 컴포넌트끼리 참조를 연결하고, 네트 모드에 맞는 `IPJTimeSource`를 주입한다.
3. `PJAbilitySet`(스탯 + 어빌리티 + 시작 효과 묶음)을 부여한다.

연결 전체 예시는 `PJAbilityDemoCharacter`에 있다.

배치는 기본적으로 컴포넌트를 액터에 두지만, 폰을 자주 교체하는 게임이면 PlayerState에 두는 쪽으로 옮길 수 있다.
